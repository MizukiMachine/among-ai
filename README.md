# among ai

## ゲーム概要

`among ai` は、AIキャラクターたちがリアルタイムに会話しながら進行するブラウザ人狼ゲームです

この版では、通常の村側推理ゲームではなく、人狼陣営をシュミレーション出来るゲームとして設計しています。ユーザーは人狼陣営の一員として、仲間の演技を見ながら村人の全排除を狙います

ゲームの中心にあるのは、正体を隠して勝つことそのものです。ユーザーは村側の推理を外から眺めるだけではなく、狼仲間が人間側を装い、占い師や村人を名乗り、疑いをそらしながら盤面を崩していく過程を人狼目線で楽しみます

## コンセプト

- 自分は必ず人狼陣営
- 仲間の正体を知ったうえで公開発言を読む
- 昼は人間側を演じ、夜は人狼として勝ち筋を相談する
- 面白さの中心は、仲間の嘘、偽CO、距離の取り方、村側への誘導
- 最終目標は村人の全排除

## このゲームで起きること

- AIキャラクターがそれぞれの役職、性格、状況に応じて発言する
- ユーザーが操作する場合は、人狼陣営として対局に参加する
- 人狼仲間は公開の場で村側を装い、秘密の場で勝ち筋を相談する
- 村側キャラクターは通常の人狼として推理し、疑い、投票する
- 公開会話、秘密会話、投票、夜行動、勝敗判定がリアルタイムに進行する
- LLM APIキーがない場合も、デモエージェントでゲームを試せる

## プレイ目標

対局設定の最初の項目として `プレイ目標` を表示します

- このゲームは人狼陣営をシュミレーション出来るゲームです
- 仲間の演技を見ながら村人の全排除を狙います

ユーザーが操作する場合、陣営選択はありません。自分は必ず人狼陣営として扱われます。そのため、以前のような `狼陣営でプレイ` ボタンは不要になり、対局設定は `プレイ目標` から始まり、その次に `参加方式` が続きます

参加人数は9人以下を推奨します。10人以上でも動作しますが、会話量、疑い先、投票候補、役職情報が増え、プレイヤーの認知負荷が高くなります

## 対局の流れ

1. `対局設定` で参加方式、キャラクター、人数を決める
2. ユーザーが操作する場合は、人狼陣営として参加する
3. 初日昼の前に、人狼陣営だけの秘密の顔合わせが始まる
4. 狼仲間が自分の正体と、昼にどう騙すかを宣言する
5. 初日昼の公開議論が始まり、人狼仲間が人間側として振る舞う
6. 村側は通常の推理ゲームとして疑い、質問し、投票先を考える
7. 夜は人狼陣営が襲撃先と翌日の演技を相談する
8. 役職行動、投票、処刑、襲撃を経て、どちらかの陣営が勝利条件を満たすまで続く

## 人狼顔合わせ

初日昼の前に、人狼陣営だけが見られる秘密の顔合わせがあります

- 人狼メンバーが互いの正体を確認する
- 各メンバーが「どう騙すか」「どう村側に見せるか」を短く話す
- 公開議論前に、狼陣営としての芝居の方向性が見える
- 村側にはこの会話は見えない
- ユーザーが人狼の場合は、仲間の演技方針を把握してから初日昼に入れる

この顔合わせは、ゲームのテーマを最初に強く見せるための場です。単なる情報共有ではなく、狼仲間が「騙して勝つ」ことを言葉にする導入として機能します

## 初日昼の会話設計

初日昼は、人狼陣営の芝居が最もわかりやすく見えるように設計しています

- 生存している人狼発言者の三分の二以上が、人間側主張または偽役職主張を行う
- `俺は人間だ` のような村側主張を行う
- `私は占い師です` のような偽役職COを行う
- 偽役職主張は単なる雰囲気ではなく、実際のCOとして内部メタデータにも記録する
- デモ発言やフォールバック発言でも、割り当てられた初日ムーブを優先する

これにより、ユーザーは人狼仲間が堂々と村側を名乗る瞬間を見られます。村側の会話としては推理ゲームが成立し、人狼側の視点では「仲間がどんな嘘をつくか」を楽しめる構造になります

## 人間プレイヤーの発言

人間プレイヤーが人狼陣営として参加している場合も、初日昼の演出ルールに入ることがあります

- 強制演技枠に入った場合は、自由入力ではなく候補選択で発言する
- 候補は人狼としての演技に合う内容にする
- 三分の二以上の狼が人間側主張を行うルールを壊さない
- プレイヤーが何を選んでも、人狼側の芝居として自然に見えるようにする

自由入力を完全に否定するのではなく、ゲームの見せ場になる初日だけは演出の一貫性を優先します

## 秘匿情報と公開発言

人狼陣営の面白さを成立させるため、秘密の情報と公開情報は明確に分けています

- 人狼だけが見る会話は、村側には表示しない
- 村側AIには、人狼側の三分の二ルールや騙り方針を見せない
- 村側AIは通常の村側推理として発言する
- 公開発言では、仲間、正体、夜相談、襲撃計画を漏らさない
- プロンプト上でも、狼専用のルールと全員共通のルールを分離する
- redaction により、見る権限のない秘密イベントはクライアントに渡さない

村側が知らない情報を本当に知らないまま動くことで、人狼側から見た「騙しの成功」や「疑いの誘導」が読みやすくなります

## 夜の人狼会話

夜は襲撃先を決めるだけの時間ではなく、翌日の演技を整えるための人狼会議として扱います

- 誰を襲撃すれば村側の連携を崩せるかを相談する
- 誰を残せば疑い先として利用できるかを考える
- 翌日の公開議論で誰を疑うか、誰をかばうかを決める
- 村人の全排除に向けて、襲撃と演技をつなげる
- 完全勝利を目指す人狼陣営の視点を維持する

昼の嘘と夜の本音が交互に出ることで、人狼陣営としてプレイしている感覚を強めています

## 画面と体験

- `対局設定`: プレイ目標、参加方式、参加キャラクター、人数を設定
- `ツアーガイド`: 人狼陣営として村人全排除を目指すゲームであることを案内
- `人狼顔合わせ`: 人狼陣営だけが見る秘密の導入
- `昼議論`: AIキャラクターが短い発言を複数巡で交わす
- `夜`: 人狼、占い師、魔女、騎士などの役職行動を処理
- `会話ログ`: 公開発言と見える範囲の秘密会話を追う
- `投票結果`: 疑い、信頼、投票、処刑結果を確認

## 主な実装方針

- 人狼側の特別ルールは、村側に見える共通プロンプトへ混ぜない
- 初日昼の演出は、プロンプトだけでなく発言スケジューラーでも制御する
- AIの発言内容と内部メタデータが食い違わないようにする
- 人間プレイヤーが入っても、人狼陣営としての構造が崩れないようにする
- APIキーなしでも動作確認できるよう、デモエージェントを残す
- UI上の説明は、村側ゲームではなく人狼陣営ゲームとして統一する

## 構成

- `src/client`: React + Vite のブラウザUI
- `src/server`: Hono API、SSEストリーム、人間入力セッション
- `src/game`: 人狼ゲームエンジン、役職ルール、勝敗判定、発言計画、秘匿情報の redaction
- `src/game/rules`: 投票、役職、勝敗、夜行動などのゲームルール
- `src/game/prompts`: 役職、フェーズ、日本語話法のプロンプト素材と組み立て
- `src/game/agents.ts`: LLMエージェントとデモエージェントの発言生成
- `src/game/speechPlanning.ts`: 初日昼などの発言計画と公開会話の流れ
- `src/server/humanSessions.ts`: 人間プレイヤーの入力待ち、候補提示、セッション管理
- `public/assets`: キャラクター画像、BGM、SFX、SF UI素材
- `tests`: エンジン、プロンプト、サーバー、UIの回帰テスト

```text
Browser UI
  -> Hono API / SSE
    -> WerewolfGame engine
      -> Speech planning
      -> Agents and prompt assembly
      -> Rules, roles, voting, night actions
      -> Redaction and human input sessions
```
