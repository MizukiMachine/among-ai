# Among AI - 機能仕様書

> AIエージェント同士が戦うリアルタイム人狼ゲームシミュレーション。
> 本仕様書はUIデザイン作成用の外部AI渡しを目的とする。

---

## 1. サービス概要

| 項目 | 内容 |
|------|------|
| サービス名 | Among AI |
| ジャンル | AI人狼シミュレーター（観戦型） |
| ユーザーの役割 | 観戦者（プレイヤーはAIのみ） |
| プラットフォーム | Webブラウザ（PC / タブレット / スマホ） |
| 技術スタック | TypeScript / React + Vite / Hono / SSE |

### 提供体験

- AIキャラクター6〜9人が自動で人狼ゲームを進行
- リアルタイムにイベントがストリーミングされる
- ユーザーは「全知全能モード（全情報見え）」か「村人モード（情報隠蔽あり）」で観戦
- 手動 or 自動でイベントを送りながら物語を追体験

## 4. UIコンポーネント詳細

### 4-1. TOPBAR

**要素:**
- サービスロゴ/タイトル: "Among AI"
- サブタイトル
- アクションボタン群:
  - 開始ボタン（ゲーム開始時に表示）
  - リスタートボタン（ゲーム中に表示）
  - 停止ボタン（ゲーム中に表示）

**状態:**
- 待機中 → 開始ボタンのみ有効
- ゲーム中 → リスタート・停止が有効、開始は無効
- ゲーム終了 → 開始ボタンが有効

### 4-2. STATUS STRIP

5カラムのステータスグリッド。

| カラム | 表示内容 | 例 |
|--------|---------|-----|
| 状態 | ゲームの状態 | 待機 / 進行中 / 終了 |
| ラウンド | 現在のラウンド数 | R1, R2... |
| フェーズ | 現在のフェーズ名 | 夜 / 昼議論 / 投票 等 |
| 生存者 | 生存プレイヤー数 | 5/7 |
| 勝者 | 勝利陣営（終了時のみ） | 村陣営の勝利 / 人狼陣営の勝利 |

### 4-3. WARNING BANNER

設定に問題がある場合に表示される警告バナー。
例: 「シナリオには8人以上のプレイヤーが必要です」

### 4-4. SETTINGS PANEL（左カラム）

ゲーム開始前に設定する項目群。各項目はラベル + コントロール。エージェント種別と要約はLLM固定で、画面上の設定項目としては表示しない。

| 設定項目 | コントロール | 選択肢/範囲 | デフォルト |
|---------|-------------|------------|-----------|
| プレイヤー数 | セレクトボックス | 6 / 7 / 8 / 9 | 7 |
| 必ず起こしたいイベント | セレクトボックス | 通常進行 / 護衛成功を再現 / ハンター発砲を再現 | 通常進行 |
| 言語 | セレクトボックス | 日本語 / English | 日本語 |
| 進行モード | セレクトボックス | 手動 / 自動 | 手動 |
| 自動速度 | スライダー | 0〜3000ms | 650ms |
| 観戦モード | セレクトボックス | 全知全能 / 村人 | 全知全能 |
| 進捗バー | プログレスバー | イベント消化率を表示 | — |

### 4-5. STORY PANEL（中央カラム）

ゲーム進行のメイン表示エリア。

#### シーンカード

現在のイベントを表示するカード。以下の要素を含む:

| 要素 | 説明 |
|------|------|
| フェーズバッジ | 現在のフェーズ名（夜/昼/投票 等） |
| 可視性バッジ | 🌐 公開 / 🔒 非公開 / 🐺 人狼のみ |
| 発言者名 | イベントの主体プレイヤー名 |
| メッセージ本文 | イベントのメッセージ |
| メタデータ展開 | 主張（Claims）/ 疑い（Suspects）/ 信頼（Trusts）を展開表示 |
| 投票詳細 | 投票イベントの場合、投票者→被投票者のマップ表示 |

#### ストーリーコントロール

| ボタン | 動作 |
|--------|------|
| 次へ（▶） | 次のイベントを表示 |
| 全て読む（⏩） | キュー内の全イベントを一気に表示 |

フォーム操作中でない場合、Enter または右方向キーでも開始/次へを実行できる。

#### ヒストリーストリップ

直近のイベント履歴を簡易表示。各イベントはアイコン + 簡略テキスト。

### 4-6. PLAYERS PANEL（右カラム）

#### 生存プレイヤーリスト

- 各プレイヤーカードに表示:
  - プレイヤー名（例: Ada, Byron, Claude...）
  - 役職（全知全能モード）/ "非公開"（村人モード）
  - 陣営（村/人狼 / 非公開）
  - ペルソナ（慎重/強気/論理派/機を見る/共感型）
  - 生存状態アイコン

#### 墓地

死亡済みプレイヤーのリスト。役職が全て公開される。

#### 主張・疑い・信頼（Claims & Reads）

- 主張（Claims）: 各プレイヤーの役職主張・占い結果報告等
- 疑い（Suspects）: 誰が誰を疑っているか + 理由
- 信頼（Trusts）: 誰が誰を信頼しているか + 理由

#### 投票マップ

最新ラウンドの投票結果を可視化:
- 誰が誰に投票したか
- 票数の集計
- 理由の表示

#### ラウンド要約

各ラウンドの終了時に生成されるサマリー。
- deterministic: ゲームエンジンが自動生成する定型要約
- LLM: AIが文脈を考慮して生成する要約

## 5. ゲームメカニクス

### 5-1. 役職一覧

| 役職 | 陣営 | 能力 | 勝利条件 |
|------|------|------|---------|
| 人狼 | 人狼 | 夜に1人を襲撃、人狼同士で秘密の会話 | 人狼が村人以上になる |
| 占い師 | 村 | 夜に1人の陣営を判別 | 全人狼を排除 |
| 魔女 | 村 | 毒薬（1回）で殺害、救命薬（1回）で蘇生 | 全人狼を排除 |
| 騎士 | 村 | 夜に1人を護衛（連続同一人物不可） | 全人狼を排除 |
| ハンター | 村 | 死亡時に1人を射殺 | 全人狼を排除 |
| 村人 | 村 | なし（投票のみ） | 全人狼を排除 |

### 5-2. ゲーム進行フロー

```
[準備] 役職割当・ペルソナ割当
  ↓
[夜フェーズ]
  ├─ 騎士: 護衛対象を選択
  ├─ 人狼相談: 襲撃対象を議論（複数人狼時）
  ├─ 人狼襲撃: 襲撃対象を決定
  ├─ 占い師: 1人の陣営を判別
  ├─ 魔女: 救命薬の使用判断 / 毒薬の使用判断
  └─ 死亡解決: 死亡処理（ハンター射殺のチェーンも解決）
  ↓
[昼フェーズ]
  ├─ 議論: 全生存プレイヤーが順に発言
  └─ 投票: 全生存プレイヤーが1人を指名
       ├─ 最多票 → 処刑（ハンター射殺の可能性あり）
       └─ 同数 → 処刑なし
  ↓
[勝利判定]
  ├─ 全人狼排除 → 村の勝利
  ├─ 人狼 ≧ 村人 → 人狼の勝利
  ├─ 規定ラウンド到達 → 数で判定
  └─ 上記以外 → 次の夜へ
```

### 5-3. AIペルソナ

各プレイヤーは以下のいずれかのペルソナを持つ:

| ペルソナ | 性格・戦略 |
|---------|-----------|
| 慎重（Cautious） | 証拠を求め、リスクの低い選択を好む |
| 強気（Aggressive） | 積極的に圧力をかけ、態度を明確にさせる |
| 論理派（Logical） | 主張・投票・タイミングの矛盾を指摘 |
| 機を見る（Opportunistic） | 情勢を見て有利な主張に乗る |
| 共感型（Empathetic） | トーンの変化を敏感に読み、信頼を築く |

### 5-4. 構造化スピーチ（発言メタデータ）

AIプレイヤーの発言には以下のメタデータが付与される:

**主張（Claims）:**
- タイプ: 役職主張 / 占い結果 / 魔女情報 / 一般
- 内容: 任意のフリーテキスト

**疑い（Suspects）:**
- 対象プレイヤー
- 理由
- 確信度（0〜1）

**信頼（Trusts）:**
- 対象プレイヤー
- 理由
- 確信度（0〜1）

## 6. 観戦モード

### 6-1. 全知全能モード（Omniscient）

- 全プレイヤーの役職が見える
- 夜の行動（護衛・襲撃・占い・魔女）が全て見える
- 人狼同士の秘密の会話が見える
- 魔女の薬の残数が見える

### 6-2. 村人モード（Village）

- 役職は「非公開」表示
- 夜の行動は伏せられる
- 人狼の会話は見えない
- 昼の議論と投票のみ見える
- 村人の視点をシミュレート

### 6-3. イベントの可視性レベル

| レベル | 全知全能 | 村人 |
|--------|---------|------|
| 公開（public） | ○ | ○ |
| 非公開（private） | ○ | ×（「非公開のイベント」として伏せられる） |
| 人狼のみ（werewolf） | ○ | ×（「非公開のイベント」として伏せられる） |


## 13. デザイン作成時の留意点

1. **観戦体験が主目的** — ユーザーは操作するのではなく「物語を追体験」する
2. **情報量が多い** — イベント・メタデータ・投票・プレイヤー状態を整理して表示する必要がある
3. **2つの観戦モード** — 全知全能モードと村人モードで表示情報が大きく変わる
4. **進行制御** — 手動（1件ずつ送る）と自動（一定間隔で送る）の2モード
5. **多言語** — 日本語/英語の両方で成立するレイアウト
6. **レスポンシブ** — PC 3カラム / タブレット・スマホではスタック
7. **ダークモードは非対応** — 現状はライトテーマのみ
