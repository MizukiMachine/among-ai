# プロンプト管理方針

このプロジェクトでは、昼の公開発言生成を「会話履歴 + 個人設定 + 役職」を中心にした単発プロンプトとして扱う。以前の構造化推理 JSON と表層セリフ生成の二段階フローは削除している。

## 採用形式

- 正本: `src/game/prompts/materials.yaml`
- 形式: `material_bundle`
- 対象: 役職ごとの非公開情報の露出制御、投票・夜行動など対象選択の JSON 契約、ラウンド要約、ペルソナ素材
- コード側: YAMLの読み込み、スキーマ検証、実行時情報の選別、秘密情報の露出制御、最終プロンプトの組み立て
- 昼の公開発言: `buildPromptContext(... mode: "public_speech")` が、人物設定、自分の役職、配役内訳、現在の状況、これまでの会話、自分の記憶、最小限の発言ルールだけを出す

## 責務分担

YAMLは、LLMに渡す静的な文言と対象選択などのルールを持つ。長い説明や戦略文は自然文のまま置き、短いルールや選択肢は配列として管理する。

アプリケーションコードは、ゲーム状態に応じた素材選択とデータ露出制御を担当する。プレイヤー名、フェーズ、履歴、役職別の非公開情報、合法ターゲットは実行時に組み立てる。公開発言では、speechPlan や agenda のような制御文はプロンプト本文に入れない。

## 発言対象の設計

昼議論の内部メタデータに `suspects` / `trusts` がある場合は、現在応答でき、投票対象にもなり得る生存者だけを対象にする。墓地のプレイヤーは死亡、過去の発言、投票履歴、占い結果などの歴史情報として参照できるが、現在の疑い先・信頼先・圧力先・処刑候補にはしない。

この制約はコード側でも `legalPlayers` として生存者のみを渡し、メタデータを同じ候補リストで正規化する。これにより、デモや人間入力補助の候補生成が墓地のIDを `suspects` に返しても公開履歴や要約には載せない。

## 昼議論の巡回設計

昼議論はAI生存者を各ラウンド2巡で回し、必要な場合だけ生存者数に応じた人数に追加発言を回す。人間プレイヤーは固定順ではなく、AI発言後に最大5回まで任意発言できる。この巡回、追加発言、任意割り込みの選定はエンジン側の進行管理であり、公開発言プロンプトには「何巡目」「この発言の設計」「初日特別モード」などの制御文を入れない。

公開セリフは、LLMに一度だけ依頼する。入力は、個人設定、自分の役職、配役内訳、役職ごとに見えてよい秘密情報、現在の状況、生存者・死亡者、これまでの公開会話、自分の記憶、最小限の発言ルールだけにする。配役内訳は人数だけで、誰がどの役職かは公開発言や自分に許可された秘密情報以外では出さない。LLMの返答はそのまま画面に出す発言として扱い、誤って JSON 形式が返った場合のみ `message` / `messages` / `speech` フィールドから発言文を回収する。`方針:` や `reasoning:` のような内部ラベルは表示しない。公開発言のメタデータは LLM に構造化生成させず、画面に出した自然文から疑い先・信頼先・役職主張だけを軽量に抽出する。

投票や夜行動などの対象選択も、自由文の理由をLLMに書かせない。LLMは `targetId` と `reasonKind` だけを返し、表示や記憶に残る理由文はコード側で `reasonKind` から生成する。

昼議論のAI発言生成は投機的なレース方式で実行する。未発言AIから複数人を並列生成し、最初に完了した発言だけを採用して公開履歴へ追加する。残りの古い文脈の生成はキャンセルまたは破棄し、更新後の公開履歴で次のレースを始める。人間プレイヤーがいる場合、昼議論では固定順の発言者にしない。AIが1人発言した後から最大5回まで任意に発言を挟める。UIでは「発言」で割り込み入力を開き、「次へ」で発言せずに次のAIレースへ進む。人間が発言した場合はその発言を公開履歴へ追加し、まだ発言していないAIだけで更新後の履歴から再レースする。これにより、採用される発言は直前までの昼の発言を見たものにする。各発言は短いまま保ち、長文の独演ではなく、短い応答の往復で人狼らしい弁明、反論、読み直しを発生させる。

## データ露出

- `public`: 公開履歴、生存者一覧、公開フェーズ情報、配役内訳
- `confidential`: 自分の役職、個人メモリ、役職ごとに許可された非公開情報
- `secret` / `forbidden`: APIキー、環境変数、許可されていない内部状態。プロンプトに含めない

役職別の秘密情報は `buildPromptContext` の allowlist で制御する。たとえば人狼は仲間とその実役職だけ、占い師は自分の占い結果だけ、魔女は薬と襲撃対象だけを受け取る。公開発言では、その秘密情報をどう使うかはプレイヤーの役職と状況判断に任せるが、人狼の正体・仲間・夜相談は公開しないルールを最小限入れる。

## 変更手順

1. 公開発言の最小プロンプトを変える場合は `src/game/prompts/builder.ts` の simple public speech context と simple speech system prompt を編集する。
2. 投票・夜行動・要約などの静的文言を変える場合は `materials.yaml` を編集する。
3. 出力JSON契約や意味が変わる場合は `version` を上げる。
4. 新しい役職、フェーズ、ペルソナ、状況キーを追加する場合は `materials.ts` の検証リストも更新する。
5. 実行時の秘密情報を追加する場合は、YAMLではなくコード側の露出制御とテストを先に追加する。
6. `npm run lint`、`npm exec tsc -- --noEmit`、`npm test` を実行する。

## 検証

`src/game/prompts/materials.ts` はYAMLを実パーサで読み込み、必須フィールド、役職・フェーズ・ペルソナの網羅、出力契約、感度分類、未宣言プレースホルダを検証する。公開発言が simple prompt のまま保たれていること、秘密情報の露出制御、対象選択の JSON 契約は `tests/prompts.test.ts` と `tests/engine.test.ts` で確認する。
